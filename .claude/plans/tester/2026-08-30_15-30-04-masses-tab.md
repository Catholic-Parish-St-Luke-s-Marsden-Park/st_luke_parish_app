## Test Strategy
- Followed `contact_screen_test.dart`'s tall-test-surface pattern: `MassesScreen`'s content (hero + 2 sections, 9 rows) exceeds the default 800x600 test surface, so the second section's rows are outside the `ListView`'s default build/cache extent. Set `tester.view.physicalSize = Size(800, 1600)` for all content-assertion tests so every row is built and findable without scrolling mid-test. (Discovered via an initial test-authoring failure — documented under Bugs Found below, not a production bug.)
- Followed `parish_screen_test.dart`'s pattern for a `MassTime` const-constructor compile check (REQ-F04-015) and for exhaustive `find.byType(Text)` sweeps to assert absence of unwanted content (address text, "carpark"/"venue" mentions, month names, emoji glyphs).
- Added a dedicated REQ-F04-017 runtime test that overrides `massScheduleProvider` with a fabricated schedule via `ProviderScope.overrides` and confirms the screen renders the overridden content instead of the real static config's Sunday rows — this is the strongest available proof the screen reads through the provider rather than importing `static_mass_schedule_config.dart` directly, since a static import vs. a provider read look identical from a pure code-reading pass at the call site.
- Extended `test/app/app_test.dart`'s `expectNoOverflowAt` pattern with a `TextScaler` axis per CLAUDE.md's explicit instruction ("extend that pattern with a text-scale axis... rather than adding a parallel helper"): swept 3 screen sizes (small phone 360x690, phone 390x844, tablet 1024x1366) × 3 text scales (default/no-scaling, `TextScaler.linear(1.5)`, `TextScaler.linear(2.0)`) = 9 combinations, each asserting `tester.takeException()` is null (REQ-F04-020). This is the first feature in this codebase to add the text-scale axis; no prior test file had one to reuse directly, so the helper was written locally in `masses_screen_test.dart` following the same shape as `app_test.dart`'s, per CLAUDE.md's instruction to extend rather than parallel it.
- Covered every REQ-F04-024-required assertion: full render (hero copy with no address subtitle, both section titles in order, all 3 "What's On" sub-group labels in order, exact row content for all 9 rows across both sections), an explicit no-icon assertion (`find.byType(Icon)` — none) plus an explicit no-emoji-glyph sweep across every rendered `Text`, and an explicit no-"Details"/chevron/arrow-affordance assertion (icon lookups + `InkWell`/`GestureDetector` absence).
- "Loading", "empty result", "parsing failure", "network failure", "missing selector result", and "invalid URL result" states are explicitly not applicable to this feature — content is fixed static config with no async/network/scraping layer — and are noted here rather than silently omitted, matching REQ-F04-024's own note.
