## Summary
- Scope: Replaces the Parish bottom-nav tab's generic `PlaceholderScreen` with real content — a hero banner (revised subtext, no eyebrow label), an "About St Luke's" section, and a 3-part "Church Leadership" section (Universal Church / Diocese of Parramatta / Parish) with locally bundled leadership images and external-link taps. Also introduces the shared app-level AppBar chrome used across all 6 tabs (parish wordmark logo, "Saint of the Day" placeholder pill, "Ask Luke" pill), and a new `lib/features/ask_luke/` feature module — a full-screen, hardcoded-response quick-reply assistant with 4 topic chips and no free-text input. The other 5 tabs' own body content (Masses, News, Ministries, Contact, Donate) is untouched; only the shared AppBar chrome they all inherit changes, identically for all of them.
- User value: Turns the Parish tab from a stub into real, navigable content, and adds app-wide chrome (branding logo + 2 quick-access pills) that every tab benefits from, including a first lightweight "assistant" surface (Ask Luke) ahead of any real backend/AI integration.
- Risks: **2 open, tracked risks** — see `.claude/risks/active-risks.md`. Both were explicitly reviewed and accepted by the user for merge-with-tracking rather than fix-before-merge (decision recorded 2026-08-26_23-58 in `.claude/memory.md`):
  - **RISK-003** ([GitHub issue #12](https://github.com/Catholic-Parish-St-Luke-s-Marsden-Park/st_luke_parish_app/issues/12)): Church Leadership entry taps (Pope Leo XIV, Bishop Vincent Long, Fr Gayan Thamel) silently fail to open an external browser on real Android devices/emulators — confirmed live during the App-Visualiser phase, root-caused to a missing `<queries>` block in `android/app/src/main/AndroidManifest.xml` (Android 11+ package-visibility requirement for `url_launcher`'s `canLaunchUrl`). The fix (adding a `<queries>` block for `https`/`http` browsable intents) is small and scoped, and is documented in issue #12, but is **not applied in this PR**. Widget tests for these taps pass because they inject a fake `UrlLauncherService` and never touch the platform channel, so this gap is not caught by the automated suite.
  - **RISK-004**: iOS `Info.plist` has no `LSApplicationQueriesSchemes` entry for the same class of gap. This is **unconfirmed either way** — no iOS run has been performed for this feature yet, so it is logged as an open risk rather than a confirmed bug.
  - Also see GitHub issues [#13](https://github.com/Catholic-Parish-St-Luke-s-Marsden-Park/st_luke_parish_app/issues/13), [#14](https://github.com/Catholic-Parish-St-Luke-s-Marsden-Park/st_luke_parish_app/issues/14), [#15](https://github.com/Catholic-Parish-St-Luke-s-Marsden-Park/st_luke_parish_app/issues/15) — App-Visualiser-phase clarification questions (section order, Parish-tab iconography, color scheme). These are not confirmed bugs; they were filed for follow-up discussion and are not blocking this PR.
  - **Reviewer note:** these risks are being shipped with tracking rather than fixed first, per explicit user decision. Please weigh in on the GitHub issues if you'd prefer RISK-003 fixed as a fast-follow vs. in a later PR.
