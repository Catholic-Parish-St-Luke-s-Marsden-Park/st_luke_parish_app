## Architecture checks (root CLAUDE.md)
- **Network calls:** none in widgets. Screens read providers only, and the datasource is reached only through the repository.
- **Failures:** typed sealed failures. The UI shows fixed friendly strings, and tests assert that no exception text leaks.
- **Generated providers:** `@riverpod`, with `.g.dart` committed alongside the source.
- **Validation:** `resolveBackendUri` was refactored to delegate to the shared `validateBackendUri`, and its 6 existing tests pass unchanged.
- **Accessibility:** the new retry target is 48x48 minimum and the new text uses `TextTheme` styles. The new states pass a 1.5x and 2.0x sweep.

## Gaps
- **RISK-013 (pre-existing):** the Ministries grid and detail hero overflow at larger text scales, and the hero also overflows at 1.0x for the longest name. This was reproduced on `main` and is not introduced here, but it is a real accessibility defect worth a follow-up.
- **RISK-012:** the fallback snapshot can drift if it isn't refreshed at release time.
- **Visualiser limits:**
  - The on-device check was scripted, not a hands-on human review.
  - The live test binding renders at 800x600, letterboxed, so the exact phone-width layout wasn't seen on the simulator. The widget-test sweeps cover it.
  - There was no Android run: this machine has no Android SDK.

**Pass, with risks carried forward.** All 22 requirements trace to code and tests. RISK-012 and RISK-013 are carried forward; RISK-013 predates this feature.
