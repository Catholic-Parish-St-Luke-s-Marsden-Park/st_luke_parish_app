## Gap Found and Closed This Phase
**Missing direct unit test for `BulletinsFeedDatasource` itself.** The existing `feed_bulletins_repository_test.dart` only exercises a *fake* datasource that already returns pre-made XML strings or pre-made failure objects — it never actually calls the real `BulletinsFeedDatasource.fetchFeedXml()` against a real (mocked) `http.Client`, so REQ-F05-001 (correct URL/timeout) and REQ-F05-012 (datasource-level conversion of a non-2xx response or a thrown client exception into `BulletinsNetworkFailure`) had no direct test evidence — only indirect coverage via the 2 live network tests, which depend on the real site being reachable and returning specific status codes to exercise the failure path (which it doesn't, under normal operation).

Added `test/features/news/data/datasources/bulletins_feed_datasource_test.dart` (7 new tests) using `package:http/testing.dart`'s `MockClient` (already available transitively via the `http` package — no new dependency added):
- HTTP 200 returns the response body verbatim.
- The request targets `ExternalLinks.bulletinsFeed` with a non-empty `User-Agent` header (regression guard for the WAF-403-on-no-UA finding documented in ADR-0004/the coder plan).
- HTTP 404, 500, and 403 responses are all converted to `BulletinsNetworkFailure` (not left as a raw `http.Response`/status code).
- A thrown `http.ClientException` is converted to `BulletinsNetworkFailure`.
- A generic thrown `Exception` is also converted to `BulletinsNetworkFailure`, not left as a raw/unhandled exception type.

All 7 pass; `flutter analyze` and `dart format . --set-exit-if-changed` remain clean after adding this file; full `flutter test` now **175 passed, 0 failed**.

## Unresolved Coverage Gaps (flagged, not hidden)
1. **Live RSS tests are not isolated/skippable for offline or sandboxed CI runs.** `bulletins_feed_live_test.dart` has no `@Tags`, `skip:`, or connectivity pre-check — it is two ordinary `test()`s inside the regular `flutter test` sweep. If network access is unavailable, `flutter test` will report these as genuine **failures**, not skips, potentially masking or being confused with real regressions in an offline/CI environment. This repo has no `dart_test.yaml` or existing tag convention to follow (checked — none exists anywhere in `test/`), so there is no established pattern to extend, unlike the `expectNoOverflowAt` case. Confirmed this phase: with network available, both live tests pass against the real feed (verified independently, not just re-trusting the coder's report). **Recommendation for a future phase (not fixed here, since introducing a new tagging convention is a project-wide test-infrastructure decision, not a per-feature fix):** add a `dart_test.yaml` with a `live` tag excluded by default, or a runtime connectivity guard that calls `markTestSkipped(...)` on failure to reach the host, so CI/offline runs don't silently fail on an environment limitation.
2. **No golden tests** for the News screen/widgets — consistent with the still-open, documented gap across every prior feature (01 through 04); not newly introduced here.
3. **Static content drift risk** (same class as 04-masses-tab, carried from the BA plan's own Risks section): the 2 static announcements and the Prayer Intentions copy have no staleness detection.
4. **RISK-003/RISK-004** (external-link launch manifest gaps, GitHub issue #12) now apply to 3 additional tap targets introduced by this feature (bulletin PDF/page links, the bulletins-archive fallback link, the Prayer Intentions CTA) — same pre-existing risk category as prior features, not a new risk class, but the surface area has grown. **RISK-005** (missing release-build Android `INTERNET` permission) is now directly relevant to News as well, since this is the app's first feature making raw `http` calls rather than loading a URL in a WebView — if unresolved before release, the bulletins fetch (not just Donate's WebView) would fail in a production build. Both carried forward for Deployer, not re-litigated here.
5. **No test exercises the datasource's actual 10-second timeout firing** (as opposed to a generic thrown exception being converted correctly, which the new `bulletins_feed_datasource_test.dart` does cover). The timeout duration is a private `static const` inside `BulletinsFeedDatasource`, not injectable, so a real timeout-firing test would need either a 10-second-long test or a refactor to inject the timeout duration — judged not worth the tradeoff for this phase; the conversion logic itself (any exception → `BulletinsNetworkFailure`) is fully covered, which is what actually matters for REQ-F05-012's "handled explicitly" requirement.
6. **No live device/emulator run** — all coverage is widget-test-level (Visualiser's phase to close), including the external-link launches, which are only proven against the fake `UrlLauncherService`, never a real platform channel (by design, matching every prior feature's precedent).
