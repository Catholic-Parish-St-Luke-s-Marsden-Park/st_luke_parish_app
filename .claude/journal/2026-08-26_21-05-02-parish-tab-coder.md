## Summary
Implemented the full approved BA plan for the Parish tab feature (REQ-F02-001 through REQ-F02-029, including REQ-F02-016a). Three architecturally distinct pieces were built as called out in the plan:

1. **Parish tab content** (`lib/features/parish/`) — hero banner with revised copy and no eyebrow, "About St Luke's" section with no icon/logo row, and a new 3-part "Church Leadership" section (Universal Church / Diocese of Parramatta / Parish) driven by a static typed config (`ChurchLeadershipEntry`/`ChurchLeadershipSection`), replacing the old separate "Parish Leadership" and "Diocese of Parramatta" cards. Deacon Tony Hoban's entry was dropped per confirmed BA decision.
2. **Shared AppBar chrome** (`lib/app/shell/` + `lib/shared/widgets/`) — the bare text-title `AppBar` was replaced with the St Luke's wordmark logo (sole branding element, no per-tab text title) and two pills, "Saint of the Day" (hardcoded coming-soon dialog) and "Ask Luke" (full-screen push). This chrome was deliberately kept out of `lib/features/parish/` since it's app-level, shared across all 6 tabs.
3. **Ask Luke** (`lib/features/ask_luke/`) — a new feature module (own ADR: `.claude/decisions/0001-ask-luke-own-feature-module.md`) for the full-screen quick-reply assistant: header, welcome bubble, 4 text-only chips in the required order, and hardcoded verbatim placeholder responses isolated in one typed config file for easy future revision. No free-text input anywhere.

Downloaded and bundled all 5 required images locally (never hotlinked) under `assets/images/branding/` and `assets/images/leadership/`, registered in a new `assets:` section in `pubspec.yaml`. Added `url_launcher` as a new dependency, wrapped behind an injectable `UrlLauncherService` (`lib/core/services/`) so external-link behavior is testable via Riverpod provider override rather than calling `url_launcher`'s top-level functions directly from widgets.

## Architecture/Standards Compliance
- Feature-first layered structure followed for both `parish` and `ask_luke` (`presentation/`, `domain/entities/`, `data/config/`)
- Shared AppBar chrome kept strictly under `lib/app/shell/` and `lib/shared/widgets/`, never under `lib/features/parish/` (REQ-F02-015)
- No business logic, scraping, or direct network calls in widgets; all content is static typed config, no scraping/parsers needed for this feature
- Typed config used throughout (`ChurchLeadershipEntry`, `ChurchLeadershipSection`, `AskLukeTopic`) — no dynamic maps
- Riverpod used for the one piece of new feature state (`selectedAskLukeTopicProvider`, generated via `riverpod_generator`), matching the established `nav_index_provider.dart` pattern from feature 01
- External URL launching centralized in `lib/core/services/url_launcher_service.dart` with basic URL validation before launch, per CLAUDE.md's "validate extracted URLs before use" rule
