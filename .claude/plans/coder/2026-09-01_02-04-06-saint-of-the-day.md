## Summary of Implementation
Implemented all 18 approved requirements (REQ-F06-001..018): replaced the "Saint of the Day" pill's "coming soon" dialog with a full-screen `SaintOfTheDayScreen` that calls OpenRouter directly (model `google/gemini-3.1-flash-lite`, prompt ported verbatim from the live Netlify function), parses the response via a ported tolerant regex-section extractor, and caches the result on-device (`shared_preferences`) keyed to today's `Australia/Sydney` calendar date behind a swappable `SaintOfTheDayCache` interface (see ADR-0005).

### Domain (`lib/features/saint_of_the_day/domain/`)
- `entities/saint_of_the_day.dart` — immutable entity (8 content fields + `dateKey`/`displayDate`).
- `failures/saint_of_the_day_failure.dart` — sealed `SaintOfTheDayFailure` with `NotConfigured`/`Network`/`Parsing` subtypes (REQ-F06-003/004/005/007).
- `repositories/saint_of_the_day_repository.dart` — abstract `getTodaysSaint()` contract.

### Data (`lib/features/saint_of_the_day/data/`)
- `datasources/openrouter_saint_datasource.dart` — direct `POST` to `https://openrouter.ai/api/v1/chat/completions` (REQ-F06-002); API key defaults to `String.fromEnvironment('OPENROUTER_API_KEY')` via a constructor parameter (REQ-F06-003) — the default-parameter form was chosen over a bare `static const` field specifically so tests can inject a fake key without needing `--dart-define`, matching this repo's existing fake-the-concrete-datasource test pattern (see `feed_bulletins_repository_test.dart`'s `_FakeDatasource implements BulletinsFeedDatasource`).
- `parsers/saint_text_parser.dart` — ported regex-section extractor (REQ-F06-006), same tolerant "missing section -> empty string, missing name -> 'Saint of the Day'" behaviour as the reference.
- `sydney_date.dart` — hand-rolled NSW DST rule for the `Australia/Sydney` cache date key, prompt date string, and display date, since a `timezone`-database package was outside the approved dependency list (`shared_preferences` only) — documented in ADR-0005, including the accepted boundary-precision trade-off.
- `cache/saint_of_the_day_cache.dart` — abstract `SaintOfTheDayCache` + `SharedPreferencesSaintOfTheDayCache` implementation (REQ-F06-010); a corrupted/old-shape cache entry is treated as a miss, not a crash.
- `repositories/saint_of_the_day_repository_impl.dart` — orchestrates cache-check -> (miss) fetch -> parse -> cache-write (REQ-F06-008/009), converting every exception into a typed `SaintOfTheDayFailure`.

### Presentation (`lib/features/saint_of_the_day/presentation/`)
- `providers/saint_of_the_day_provider.dart` — `@riverpod` `saintOfTheDayRepositoryProvider` (async, wires `SharedPreferences.getInstance()`) and `saintOfTheDayProvider` (`AsyncValue<SaintOfTheDay>`, REQ-F06-011). **Not yet compiled** — see Deferred/Follow-up below; `part 'saint_of_the_day_provider.g.dart'` has no generated file on disk yet.
- `screens/saint_of_the_day_screen.dart` — `Scaffold`+`AppBar` (default back button via push navigation, matching `MinistryDetailScreen`'s precedent), explicit loading/error/data `AsyncValue.when` branches, per-failure-type user-facing messages (REQ-F06-011).
- `widgets/` — `SaintOfTheDayHeader` (date pill + name + feast, gold/navy gradient, no icon), `SaintOfTheDaySectionCard` (plain-text label, optional "emphasized" gold treatment for the closing Prayer section — REQ-F06-013: no icon/emoji anywhere), `SaintOfTheDayLoadingView`, `SaintOfTheDayErrorView` (48x48 "Try again" retry action — REQ-F06-012).
