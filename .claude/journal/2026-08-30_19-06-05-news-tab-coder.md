# Journal — Coder phase, 05-news-tab

2026-08-30_19-06

Implemented all 38 approved requirements (REQ-F05-001..038) for the News tab, replacing the `PlaceholderScreen` stub with the app's first real network/async feature: a live "Latest Bulletins" section (WordPress RSS feed + regex extraction), a static "Parish News" section (2 entries), and a static "Submit a Prayer Request" section.

Key points:
- Before writing any code, fetched the real feed (`https://stlukesmarsdenpark.org.au/category/bulletins/feed/`) via `curl` to independently verify the BA plan's carried-over assumptions rather than trusting the reference app's fixture-based confidence, per CLAUDE.md's scraping test rules and the BA plan's explicit flag. Found and worked around one real surprise: the host's WAF returns HTTP 403 to a generic/no `User-Agent` — a descriptive UA (matching the reference app's own header) is required. Everything else matched: `<item>`/`content:encoded`/`description`/`pubDate` element names, PDF `href` markup inside `content:encoded`, and RFC 822/1123 `pubDate` format.
- Ported the reference app's `rss_bulletin_parser.dart` mechanism (XML iteration + PDF-link regex + self-contained RFC 822 parser) rather than re-deriving it from scratch, since it's proven working logic against this exact site — documented via `.claude/decisions/0004-news-rss-regex-vs-css-selector.md` per the BA plan's explicit ADR requirement (REQ-F05-033).
- Built a full layered pipeline: `BulletinsFeedDatasource` (http fetch, timeout, typed network-failure conversion) → `parseBulletinsRss` (xml parse, typed parsing-failure conversion, per-item defensive handling of bad `pubDate`) → `FeedBulletinsRepository` (URL validation, explicit descending-pubDate sort independent of feed order, mapping to the typed `Bulletin` entity, with a catch-all defensive fallback converting any unexpected exception to a typed failure) → `bulletinsProvider` (`@riverpod`, `AsyncValue<List<Bulletin>>`, autoDispose) → `BulletinsSection` (`.when(loading, error, data)`, including a shared empty/error message widget with a "View bulletins on the parish website" fallback link).
- No `freezed` added for the typed failures — used plain Dart 3 `sealed class`es (`BulletinsFailure`/`BulletinsNetworkFailure`/`BulletinsParsingFailure`), consistent with this app not having adopted `freezed` for any other feature yet and the BA-approved dependency list being `http`/`xml` only.
- Added `httpClientProvider` to `lib/core/network/` (cross-cutting, hand-written `Provider<http.Client>`, matching the existing `urlLauncherServiceProvider` style) rather than constructing an `http.Client` inline in the News feature, so a future network-capable feature can reuse it.
- Real bug caught by the text-scale overflow sweep (not by inspection): `BulletinListTile`'s date + "Download PDF ↗" pair was a fixed-width `Row` with `spaceBetween`, which overflowed at `TextScaler.linear(1.5)`/`(2.0)` on phone-width screens. Fixed by switching to a `Wrap`, mirroring `MassRow`'s existing precedent for the same class of problem. Re-ran the full sweep after the fix — clean.
- No icons/emoji anywhere; "LATEST"/"PREVIOUS" and "Download PDF ↗"/"Submit Prayer Request ↗" kept as plain text per the approved mockup and the Masses tab's zero-`Icon`-widget precedent.

`flutter analyze` clean; `dart format . --set-exit-if-changed` clean. `dart run build_runner build --delete-conflicting-outputs` generated `bulletins_provider.g.dart`, committed alongside its source. `flutter test`: **168 passed, 0 failed** — includes fixture-based parser/repository/provider unit tests, a full News-screen widget-test suite (sections/order, all `AsyncValue` states, exact content, no-icon/emoji sweep, text-scale/screen-size overflow sweep), and 2 live integration tests against the real RSS feed (resilient shape assertions, not brittle exact-content checks) which both passed against the live site during this session. Also removed the now-obsolete `NewsScreen` case from `test/features/placeholder_screens_test.dart`'s shared table (News was the last remaining genuine placeholder; no destination remains in that table now).

Flagged, not fixed in this phase: RISK-005 (missing release-build Android `INTERNET` permission) is now directly relevant to News as well as Donate, since this is the app's first feature making raw `http` calls rather than loading a URL in a WebView — a Deployer-phase concern, not `lib/`/`test/` code. The 2 live feed tests require network access and would fail in a fully offline/sandboxed test run for environmental reasons, not a code defect; the fixture-based unit tests provide full network-independent coverage of the same logic.
