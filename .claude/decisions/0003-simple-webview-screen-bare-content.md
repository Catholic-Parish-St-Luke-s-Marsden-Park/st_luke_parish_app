- **Decision ID:** ADR-0003
- **Title:** `SimpleWebViewScreen` renders bare content only (no own `Scaffold`/`AppBar`), deviating from the reference app
- **Feature:** 03-multi-pages
- **Date:** 2026-08-27
- **Status:** accepted
- **Context:** The BA plan (ported from the sibling reference app `st_luke_frontend_app`) described `SimpleWebViewScreen` as taking "a URL and an AppBar title" and rendering its own `Scaffold`/`AppBar`. In the reference app, its `SimpleWebviewScreen` is pushed as a standalone route from a side drawer. In this codebase, Donate is a bottom-nav *tab*, and `AppShell` (established in 02-parish-tab, REQ-F02-016a) already owns a single shared `Scaffold`/`AppBar` (wordmark logo + Saint of the Day/Ask Luke pills, deliberately no per-tab text title) that every tab body renders inside, matching the pattern already used by `ParishScreen`, `MinistriesScreen`, `ContactScreen`, etc. (none of which have their own `Scaffold`/`AppBar`). Giving `DonateScreen`/`SimpleWebViewScreen` its own nested `AppBar` titled "Donate" would render two stacked AppBars and duplicate/contradict the shared chrome the BA plan's own Out-of-Scope section says must stay unchanged.
- **Decision:** `SimpleWebViewScreen` renders only the `WebViewWidget` + loading overlay + error state — no `Scaffold`/`AppBar`. It keeps an optional `title` parameter (unused internally) for any future caller that pushes it as a standalone route (e.g. a future Prayer Request webview reached from the side drawer) and wants to wrap it in their own `Scaffold`/`AppBar`. `DonateScreen` composes it directly as tab-body content, with no title passed.
- **Alternatives Considered:**
  - Match the reference app exactly (own `Scaffold`+`AppBar`) — rejected: produces a visibly broken double-AppBar UI when embedded as a bottom-nav tab body, and conflicts with the BA plan's explicit "unchanged shared AppBar chrome" out-of-scope boundary.
  - Make `AppShell` conditionally suppress its own `AppBar` for the Donate tab — rejected: significantly bigger, riskier change to shared shell code for a single tab, out of proportion to this feature's scope.
- **Consequences:** `SimpleWebViewScreen` is genuinely reusable both as tab-body content (current use) and, later, as a pushed standalone route (via a thin wrapper `Scaffold`/`AppBar` built by the caller) without modification. Any future feature reusing this widget as a pushed route is responsible for wrapping it in its own `Scaffold`/`AppBar` using the `title` field.
