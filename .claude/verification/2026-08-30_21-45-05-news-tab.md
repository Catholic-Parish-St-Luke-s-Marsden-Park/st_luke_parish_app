## ADR-0004 Substance Check

Read the full ADR text directly. It contains a genuine Context section (explaining CLAUDE.md's CSS-selector-first default and why it doesn't anticipate a feed+regex mechanism), a specific Decision (RSS+regex, with the exact regex and fallback chain), a real Alternatives-Considered section (CSS-selector scrape of the rendered page — rejected as unproven/unverified; XPath — rejected as not applicable since no page-DOM scraping happens at all), and a Consequences section that names a real, specific risk (the regex's narrow `href="...\.pdf..."` scope) and its concrete mitigation (the `<link>` fallback). The live-verification evidence (`curl` with a descriptive `User-Agent`, confirming the host's WAF 403s a default/no-UA request) is documented, not merely asserted. This is not a stub or rubber-stamp ADR.

**Rationale holds up:** reusing a proven, working RSS+regex implementation from a sibling reference app already built against this exact parish site is materially lower-risk than an unverified from-scratch CSS scrape of a page section (`/#bulletins`) whose DOM structure had never been inspected or selector-mapped by any prior session. The deviation is explicitly scoped to *mechanism only* — the RSS feed is the same public parish content a CSS scrape of the rendered page would read, so CLAUDE.md's "public content only" rule is fully honored; no admin/private endpoint is used. This matches the precedent and bar set by ADR-0001/0002/0003.
