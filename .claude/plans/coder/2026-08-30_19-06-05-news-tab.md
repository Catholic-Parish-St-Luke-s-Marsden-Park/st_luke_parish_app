## Summary of Implementation
Replaced the News tab's `PlaceholderScreen` stub with a real screen per all 38 approved requirements (REQ-F05-001..038): a live "Latest Bulletins" section (RSS + regex, `AsyncValue`-driven), a static "Parish News" section (2 entries), and a static "Submit a Prayer Request" section. This is the app's first real network/async feature.

### Domain (`lib/features/news/domain/`)
- `entities/bulletin.dart` — typed, immutable `Bulletin` (`title`, `pageUrl`, `pdfUrl`, `date` (`DateTime?`), `displayDate`).
- `entities/announcement.dart` — typed, immutable `Announcement` (`badge`, `title`, `body`, `date`).
- `failures/bulletins_failure.dart` — sealed `BulletinsFailure` with `BulletinsNetworkFailure`/`BulletinsParsingFailure` subtypes (plain Dart 3 sealed classes; no `freezed` added, since this app doesn't use it elsewhere yet and the BA-approved dependency list is `http`/`xml` only).
- `repositories/bulletins_repository.dart` — abstract `BulletinsRepository` contract (`Future<List<Bulletin>> getBulletins()`).

### Data (`lib/features/news/data/`)
- `datasources/bulletins_feed_datasource.dart` — fetches `ExternalLinks.bulletinsFeed` via an injected `http.Client`, with a 10s timeout and a descriptive `User-Agent` header (required — the host's WAF 403s a default/no-UA request, confirmed via live `curl`). Converts every network exception/non-2xx response into `BulletinsNetworkFailure`.
- `parsers/rss_bulletin_parser.dart` — ported from the reference app's `rss_bulletin_parser.dart`: `xml`-based `<item>` iteration (capped at 6), PDF-link regex (`href="([^"]+\.pdf[^"]*)"`, case-insensitive) against `content:encoded` falling back to `description`, `<link>` fallback when no PDF match, and a self-contained RFC 822 `pubDate` parser (no `dart:io` dependency). Throws `BulletinsParsingFailure` on malformed XML; per-item issues (bad `pubDate`) are handled explicitly, never thrown.
- `repositories/feed_bulletins_repository.dart` — the sole `BulletinsRepository` implementation: fetch → parse → URL-validate (drops any item whose resolved link fails `Uri` scheme/host validation) → explicit descending-`pubDate` sort (undated items sort last, independent of feed order) → map to `Bulletin` (with a formatted `displayDate`). Wraps the whole pipeline in a `try/catch` that converts any unexpected exception into `BulletinsParsingFailure` as a defensive fallback, per CLAUDE.md's "do not swallow exceptions silently" rule.
- `config/static_announcements_config.dart` — exactly 2 `Announcement` entries, exact approved copy (the reference app's "Sacramental Programme 2026" third entry is dropped).
- `config/prayer_intentions_config.dart` — static quote/body strings; the CTA/fallback URLs themselves live in `ExternalLinks` (core), not duplicated here.

## Bug Found & Fixed During Implementation
The first `BulletinListTile` draft laid out the date + "Download PDF ↗" pair in a fixed-width `Row` with `MainAxisAlignment.spaceBetween`. The text-scale/screen-size overflow sweep (REQ-F05-036) caught a real `RenderFlex` overflow at `TextScaler.linear(1.5)`/`(2.0)` on phone-width screens — the two texts no longer fit side-by-side at larger scale. Fixed by switching to a `Wrap` (same pattern as `MassRow`'s time+name pair), so the date and download-link reflow onto their own line instead of overflowing. Re-ran the full overflow sweep after the fix — all screen-size × text-scale combinations pass.
