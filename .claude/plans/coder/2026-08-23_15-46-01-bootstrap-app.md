## Risks / Follow-ups
- Pinned `flutter_riverpod`/`riverpod_annotation`/`riverpod_generator`/`go_router`/`google_fonts` to the same major versions used by the reference sibling app (all currently-stable 2.x/14.x/6.x lines) rather than the newest available majors (`riverpod`/`flutter_riverpod` 3.x, `go_router` 17.x, `google_fonts` 8.x) surfaced by `flutter pub get`. Those newer majors include breaking API changes; upgrading is a deliberate follow-up decision for the team, not something to absorb silently inside a shell-bootstrap slice.
- No physical/simulator device was exercised in this sandboxed session (`flutter analyze`/`build_runner`/`format` only). Tester phase should run the app on an iOS simulator and an Android emulator/tablet size to confirm REQ-F01-001 and REQ-F01-006 visually.
- Nav destination set (6 bottom + 2 drawer) was carried over from the BA plan/sibling reference as scoped; if the parish app's final feature list differs, `bottom_nav.dart`/`side_drawer.dart` will need follow-up changes (already flagged as a risk in the BA plan).
- Placeholder screens will need to grow into full `presentation/domain/data` feature folders in later slices — expected rework, not waste.
